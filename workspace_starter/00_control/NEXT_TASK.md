# Первое поручение — безопасная разведка среды

1. Прочитай AGENTS.md, PROJECT_CONTEXT.md, STATE.md и четыре стартовых reference-документа, если они есть. Кратко перечисли прочитанные пути и отсутствующие файлы. Не загружай весь каталог в контекст.
2. В текущем workspace создай недостающие подпапки из START_HERE.md только после одобрения владельцем file-write. Не удаляй и не перезаписывай существующие пользовательские материалы.
3. Проверь реально доступные tools текущей оболочки и её версию. Для имеющегося разрешённого terminal допустимы read-only проверки версий известных программ; никаких installs, profile reads, environment dumps, рекурсивного сканирования C: или admin. Заполни INVENTORY.md. Чего не видишь — пометь неизвестным и запроси только нужный screenshot/version, без secrets.
4. Проведи один filesystem test: создай новый файл в `90_runs/<shell>/<run_id>/`, прочитай обратно и проверь содержимое. Не называй это browser/MCP/model-quality тестом.
5. Если встроенный web/read tool уже доступен, прочитай одну публичную страницу документации, сохрани URL, время, извлечённый проверяемый факт и ограничения. Если web tool нет — пометь blocked, не симулируй поиск.
6. Сопоставь условия одного первого browser-подключения: OpenCode Browse / BrowserSkill / уже доступный вариант. Не выбирай «всегда лучший» и не ставь всё. Предложи один конкретный кандидат для текущей пробы с альтернативой и карточкой изменений/прав/стоимости/отмены. Синтаксис для текущей версии подтверждай первичной документацией; отсутствие поддержки запиши честно.
7. Остановись до установки/смены настроек. Дай владельцу короткий итог: проверено, артефакты, блокеры, точное одно следующее подтверждение. Обнови STATE.md.

Это настройка транспорта, а не выбор ниши. Не запускай широкий research до проверки, что действительно можешь читать источники и сохранять provenance.
