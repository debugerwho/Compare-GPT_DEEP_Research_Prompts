# ChannelLab: как начать на Windows 10

Это стартовый комплект для владельца, не installer. Создание папок не устанавливает skills/MCP и не подключает аккаунты. Ни одна local-конфигурация OpenCode/ZCode здесь не объявлена проверенной.

## 1. Где создать папку

Предлагаемый путь: `%USERPROFILE%\ChannelLab` — обычно `C:\Users\ВашеИмя\ChannelLab`. Если нужно больше места для видео — `D:\ChannelLab`. Не использовать Desktop/Documents под OneDrive, системные каталоги или папку downloads. Убедиться, что выбранный путь не синхронизируется с облаком без намерения владельца.

Обычный PowerShell, **без администратора**. Эти команды только создают отсутствующие папки; не удаляют файлы и не меняют ExecutionPolicy:

```powershell
$root = Join-Path $env:USERPROFILE 'ChannelLab'
$folders = @(
  '00_control', '00_control/reference',
  '10_sources', '20_research', '30_portfolio',
  '40_production', '50_languages', '60_publish', '70_analytics',
  '80_tools/skills_review', '80_tools/config_examples',
  '90_runs/opencode', '90_runs/zcode', '99_inbox'
)
New-Item -ItemType Directory -Path $root -Force | Out-Null
foreach ($folder in $folders) {
  New-Item -ItemType Directory -Path (Join-Path $root $folder) -Force | Out-Null
}
Write-Output $root
```

Альтернатива — создать те же каталоги через Проводник. Команды PowerShell в этой сессии не исполнялись на Windows; проверена только документация/структура комплекта.

## 2. Для чего подпапки

```text
ChannelLab/
  AGENTS.md                 правила работы; загрузку подтвердить в оболочке
  START_HERE.md             эта инструкция
  00_control/               контекст, состояние, следующий шаг, инвентарь, решения
    reference/research/     копия выбранных материалов нашего GitHub-проекта
  10_sources/               разрешённые исходники, extracts, provenance
  20_research/              вопросы, спрос, ответы конкурентов, gaps, evidence
  30_portfolio/             сравнительная экономика и будущий выбор 5–7 ниш
  40_production/            собственные сценарии, recordings, проекты/экспорты
  50_languages/             локализация, TTS, captions, human QC по языкам
  60_publish/               drafts, metadata, credits; не автоматическая публикация
  70_analytics/             полученные данные и выводы после выпуска
  80_tools/                 проверяемые skills и ОБЕЗЛИЧЕННЫЕ config examples
  90_runs/opencode/         отдельные результаты и logs без secrets
  90_runs/zcode/            тот же протокол во второй оболочке
  99_inbox/                 новые недоверенные материалы; не auto-execute
```

Одной общей папки достаточно для старта, **но не запускайте обе оболочки одновременно на редактирование общих файлов**. Разделены runs, не обязательно программы и их config. Позже можно перейти к изолированным копиям задач, если это нужно параллельной работе.

## 3. Что скопировать из GitHub

Откройте текущую рабочую ветку проекта на GitHub, `Code → Download ZIP`, распакуйте. Архив кода проекта не должен исполняться ради распаковки. Либо используйте уже имеющуюся локальную копию именно этой ветки.

Из `workspace_starter/` скопируйте **содержимое** в ChannelLab: AGENTS.md и START_HERE.md в корень, содержимое 00_control в одноимённую подпапку. При существующих файлах не подтверждайте слепую замену: сравните версии/сделайте резервную копию.

В `ChannelLab/00_control/reference/research/` положите:

- `research/LOCAL_PILOT_CONTEXT.md`;
- `research/STAGED_TOOL_CATALOG.md`;
- из `research/community/`: `VIBECODING_REVIEW.md`, `TRIALS.md`, `TOOL_CANDIDATES.md`, `tool_candidates.json`.

Сохраните подпапку `community/`, чтобы относительные пути этих материалов были понятны. Индексы/verification JSON и A/B reports можно добавить позднее по необходимости; не нужно каждый раз прикреплять всё в чат. Runtime validation script каталога рассчитан на исходный GitHub repo, а не урезанную reference-копию.

Пока не нужны: вся Telegram HTML/фото-библиотека, все 115 кандидатов в виде установок, весь диск с видео, OAuth export, secrets, пароли, cookies, основной browser profile и полные конфиги оболочек. Позднее дать разрешённый маленький sample для конкретной пробы.

Большие recordings/models/exports не помещать в Git по умолчанию. Этот комплект не инициализирует Git и не выгружает рабочую папку в облако. Резервное копирование и публикацию очищенных документов согласовать отдельно.

## 4. Как открыть в OpenCode / ZCode

В имеющейся версии выберите проект/рабочую папку ChannelLab. Названия UI-кнопок отличаются; нельзя обещать конкретную кнопку без version/screenshot. Если приложение вообще не умеет локальные файлы/terminal, это надо установить до поручения ему установки tools.

Начните с одной оболочки, затем повторите ту же первичную задачу во второй. Прикрепите/укажите AGENTS.md и файлы 00_control. Попросите перечислить прочитанные пути: AGENTS.md не следует считать загруженным автоматически.

Первый запрос:

> Работаем в ChannelLab. Прочитай AGENTS.md, 00_control/PROJECT_CONTEXT.md, STATE.md и NEXT_TASK.md; выполни NEXT_TASK.md. Покажи, какие файлы реально прочитал. Сначала безопасная инвентаризация и проверка files/имеющихся tools. Ничего не устанавливай, не подключай аккаунты, не меняй настройки и не запрашивай secrets. Перед первым browser-подключением покажи один конкретный вариант, альтернативу и карточку изменений/прав/расходов/отмены; дождись моего подтверждения. Не выбирай пока нишу и не подменяй результат планом.

Выдайте разрешение на чтение/новые рабочие файлы в пределах этой папки. Не включайте безусловное одобрение всех terminal/network/installation действий. AGENTS.md — инструкция, не sandbox; реальные permissions задаются настройками приложения/ОС.

## 5. Connector ≠ MCP ≠ skill ≠ CLI

| Слой | Что делает | Как подключать |
|---|---|---|
| Model/provider | Даёт модель агенту | Штатный provider UI/OAuth или поддерживаемый local secret mechanism; subscription/API различаются |
| Native connector | Авторизованный доступ к внешнему app внутри конкретного продукта | Официальный integrations UI этой оболочки, если он действительно существует; человек проходит OAuth/consent |
| MCP server | Предоставляет tools агенту | Проверить поддержку именно текущей версии; local stdio/remote transport, точный format, зависимости и права |
| CLI | Запускается через terminal | Требует shell и установленный executable; сам по себе не MCP |
| Skill | Описание процедуры, иногда scripts/references | Проверить SKILL.md, scripts/requirements/license и реальный discovery path оболочки; затем подключить документированным способом |
| Project/workflow | Готовая система из нескольких слоёв | Проверить её own runtime, models/accounts и цену; не считать папкой skills |

Включённые в Arena/другом чате connectors **не переходят автоматически** в локальные OpenCode/ZCode. Для старта не нужен cloud connector: reference-файлы уже лежат локально. Не нужен отдельный filesystem MCP, если оболочка уже безопасно читает/пишет workspace.

Не выдумывать универсальный `mcp.json`/путь skills. `80_tools/skills_review` — **место ревью**, не обещание autodiscovery. Пока путь не подтверждён, агент может прочитать проверенный skill как документ и выполнить доступную процедуру, но обязан назвать это ручным применением, не успешной plugin-installation.

## 6. Первые подключения — по одной функции

1. Model/provider и files/terminal capabilities: убедиться, что агент реально работает. Оплата/GLM/Plus не предполагаются автоматически.
2. Один browser/read путь после вашего одобрения: OpenCode Browse, BrowserSkill или уже доступный вариант. Не ставить все одновременно; public test без личных logins. Выбор не определяет весь будущий stack.
3. Один skill/workflow после рабочего транспорта: например, evidence collection/First Customer Finder на нескольких seeds либо wiki provenance. До этого проверить оригинал, dependencies, license, Windows и модельные расходы.
4. Cloud files/X/YouTube own-account/TTS — только под конкретную задачу и отдельно после public tests, с минимальными scopes. Автоматическую публикацию не разрешать на этапе настройки.

Git clone/npm/pip/installer/extension выполняются только после review и вашего подтверждения. Не вставлять `curl|bash`/`irm|iex` из случайного поста; Node/Python/Git не устанавливать повторно, если уже есть подходящие версии. Lightpanda требует WSL2 на Windows; WSL не устанавливать без отдельного решения.

## 7. Что можно поручить самому агенту

Агент может прочитать контекст, инвентаризировать видимые возможности, предложить точный install/config diff, подготовить обезличенный пример, после одобрения выполнить поддерживаемую установку, проверить tools и сохранить доказательства. Вы входите в аккаунты/2FA и одобряете права/расходы сами.

Не может честно обещать: все plugins под любой оболочкой, произвольную модель без provider access, рабочий account connector без login, установленный tool без проверки, безопасность на основании одного README или хорошие языковые голоса без reviewer.

Промпт для следующих сеансов:

> Прочитай AGENTS.md и 00_control: PROJECT_CONTEXT.md, STATE.md, NEXT_TASK.md. Продолжи только согласованный следующий шаг. Сначала назови фактическое состояние, не повторяй завершённые установки. В конце сохрани результаты и обнови STATE.md; следующие действия, требующие подтверждения, перечисли отдельно.

## 8. Первый ожидаемый результат

Не готовые каналы и не каталог установленного софта, а:
- заполненный INVENTORY.md с неизвестными, а не догадками;
- отдельный run с успешным files/read test;
- факт доступности/отсутствия web tools;
- один обоснованный запрос на подключение следующей функции;
- STATE.md, с которым новая сессия продолжит без пересказа всей истории.

Чтобы дать **точные UI-шаги MCP/skills**, нужны версии OpenCode и ZCode и при необходимости скриншоты разделов tools/integrations. Секреты и полные configs не присылать.
