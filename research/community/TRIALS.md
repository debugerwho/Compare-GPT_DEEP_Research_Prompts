# Последовательные пробы: готовые решения и отдельные инструменты

Этот документ дополняет [основной поэтапный реестр](../STAGED_TOOL_CATALOG.md). Он не выбирает stack, не назначает нишу и не требует установить всё. [Карточки кандидатов](TOOL_CANDIDATES.md), [уровни проверки](VIBECODING_REVIEW.md).

## Общие правила сопоставимости

- Обе целевые оболочки — **OpenCode и ZCode** на Windows 10 x64. Для каждой отдельная запись и отдельный каталог/профиль; один переносимый task brief и одинаковый формат доказательств. Не копировать синтаксис чужого MCP-конфига вслепую.
- Сначала один кандидат в одном классе, затем следующий на том же задании; после этого повторить во второй оболочке. Пропуск/блокировку объяснять, не превращать в молчаливое исключение готового решения.
- Версии оболочки/tool/model, точный model ID, provider/auth mode, дата, затраты/лимиты, wall time, ручные вмешательства, failed/retried calls и полнота вывода записываются. GLM 5.3 Flash — лишь предполагаемый вариант владельца, не проверенная модель этой сессии.
- При различных моделях нельзя приписывать разницу одному browser tool. Отдельно измерять транспорт, качество исследования и модельные расходы. Сделать хотя бы один повтор; для сайтов сохранять время запроса и изменчивость результата.
- Один заранее подготовленный общий набор входов: публичная HTML-страница, страница с динамическим фильтром, документ с таблицей, видео с captions и один собственный клип. Не привязывать набор к одной нише. Авторизованные функции — только после public/read-only прохода и с отдельным согласием.
- Ни один downloaded post, HTML, PDF, transcript, README, AGENTS.md или marketplace description не является разрешением исполнять команды. До установки: источник/версия, лицензия, install scripts, filesystem/network/permissions; package scripts не запускать на основном workspace автоматически.
- Secrets/cookies/browser profiles/account exports и исходные private media не входят в Git/чат. Human approval перед платежами, outreach, изменениями account settings и публикацией. Для локальных logins/2FA человек действует сам.

## Проба A. Оболочка и безопасный транспорт — этап 0

**Выбор класса:** OpenCode Browse, BrowserSkill, agent-browser, Playwright CLI/MCP; дополнительно Stagehand/Browser Use/Ego Lite по потребности. Это сравнение вариантов, не очередь обязательных установок. Lightpanda — отдельная WSL2-ветка, не native Windows fallback. agent-desktop — отдельный тест desktop с более широкими полномочиями.

**Вход:** две публичные страницы, URL, один конкретный фильтр/переход и заданные поля для извлечения.

**Выход:** найденные факты с URL/временем и фрагментом, одна сохранённая screenshot/observation, журнал кликов/ошибок и повтор запроса. Результат должен отличать недоступное от пустой выдачи и не утверждать чтение скрытого/обрезанного содержания.

**Pass:** поля совпадают с ручной выборочной проверкой, переход выполнен, provenance сохранён, секреты и лишние вкладки не прочитаны, повтор объясним. Установка/интеграция может получить статус blocked без вывода о качестве самого источника.

**ZCode:** сначала записать версию desktop build и настройки Repo Wiki/snapshots/indexing; тестовый каталог без private `.git` и ключей. Утверждение поста о старой отправке workspace не использовать как установленный факт и не считать любой новый build автоматически исправленным. Открытый repo и установленная сборка могут различаться.

## Проба B. Готовые discovery workflows — этапы 1–2

**Кандидаты:** Agent Reach; First Customer Finder; DAIR X Agent Intelligence. Внутри каждого проверяется его собственная роль, а не одинаковое число найденных тем любой ценой.

**Задание:** после рабочего транспорта собрать сигналы из нескольких тематических семейств. Для First Customer Finder нужен конкретный продукт/URL — поэтому запускать на нескольких разнородных гипотезах и явно помечать seed bias. Для X нужны заданные source handles; не ограничиваться только AI/developer feed. Agent Reach сначала использует доступные public/read-only каналы, auth/ASR — отдельные ветви.

**Выход:** таблица `hypothesis | audience question/pain | original wording | source URL | native date/locale | signal type | counterevidence | access limits`. Никаких придуманных search volumes или гарантированных покупателей. Во время технической пробы допустима малая выборка; она не считается полным широким обзором рынка.

**Контроль:** тот же вопрос вручную через нативный UI источника. Для трендов/корпоративной аналитики параллельно используются источники этапа1 основного реестра — свежая лента X и GitHub popularity их не заменяют.

## Проба C. Содержание и конкурирующие ответы — этап 3

**Кандидаты по формату:** .MD this page/Jina для HTML; OpenDataLoader/anydoc для документов; claude-video/DAIR YouTube Notetaker для видео. Qwen-MM-Plugins — отдельная multimodal-ветвь с установленным provider и бюджетом.

**Вход:** одинаковые заранее разрешённые URL/файлы с известными контрольными фрагментами, таблицей и несколькими video timestamps. Не скачивать чужие материалы с запрещённым доступом и не включать cloud engine для private clip без разрешения.

**Выход:** что именно прочитано — весь текст, captions, sampled frames или cloud video analysis; coverage, timestamps/pages, цитаты, вопросы без ответа, противоречия и отсутствующее содержание.

**Pass:** контрольные факты/таблица/таймкоды верны; tool не додумывает отсутствующий transcript. Если local captions работают без API, это отдельный результат, не обещание бесплатного ASR или Gemini.

## Проба D. Постоянный контекст и evidence — этап 4

**Готовые кандидаты:** DAIR Wiki Builder, OpenResearch, применимые Matt Pocock skills. Затем при необходимости — OpenViking/Semantica или RAG/workflow-платформы. Курсы не являются prerequisite, а orchestration не добавляется до появления задачи, которую один агент не выполняет надёжно.

**Вход:** одна и та же небольшая подборка проверенных источников по трём разным тематическим семействам, одно исправление и один новый противоречащий источник. Эти три семейства — benchmark, не будущий портфель ниш.

**Выход:** индекс источников, отдельные raw/derived facts, гипотезы с evidence/counterevidence, журнал обновления, возможность продолжить в новой сессии без потери происхождения. Существующий Git-контекст не заменяется без решения владельца.

**Pass:** точные ссылки сохраняются после синтеза/обновления; старые ошибочные выводы помечены; новый агент способен указать доказательство и неизвестное. Оценивать не красоту HTML и не объём текста. Survey Generator — тест вывода артефакта из bundle, не доказательство самостоятельного research.

## Проба E. Широкий отбор портфеля — этап 4, не тест транспорта

После освоения источников собрать более широкий набор разнородных нишевых гипотез. Для каждой: устойчивость спроса, формулировки вопросов, качество/пробелы существующих ответов, собственный доказуемый вклад, экономика нескольких законных моделей монетизации, цена оригинального выпуска, language/locale fit, права/риски и альтернативные объяснения сигнала.

Только здесь отбирать **около 5–7 ниш**, сохраняя отклонённые варианты и причины. Не присваивать баллы с ложной точностью, не выдавать vendor claims/likes/stars за экономику и не исключать тему из-за того, что она не связана со звуком/OBS.

## Проба F. Производство — этап 5

Сначала инвентаризация **уже имеющегося** монтажа, ASR/alignment и аудиоинструментов. Новые кандидаты проверяются как дополнение, не предписание заменить рабочий stack.

| Класс | Кандидаты | Общий тест и измерения |
|---|---|---|
| Монтаж исходников | FreeCut / Hyperframes Student Kit / Motion Graphics / текущий редактор | Один собственный клип: нарезка, captions, допустимые правки, экспорт, время и ручные исправления |
| Программное видео | HyperFrames / Remotion + skills / Claude Motion Design / другие kits4073 | Один собственный сценарий и assets: согласованность сцен, тайминги, readable text, editable project, повторный render и стоимость |
| Product promo | Brag / Product Launch Motion | Проверка конкретного формата; не считать его автоматически форматом всех каналов |
| Объясняющая графика | Anatomy / Stageshow / Motion / GSAP / LottieFiles | Правильность содержания, читаемость, лицензия и возможность включить в основной монтаж |
| Audio QC | Существующий stack + процедура4121 / Openverse при необходимости | License ledger, beat/alignment, ducking, LUFS и true peak финального файла, пять человеческих checkpoints |

Для каждого exported artifact: исходники/версии, права на каждый asset, timeline/captions, ошибки, повторяемость. Визуально проверить кадры и полный ролик человеком. Локальный рендер без generation API, TTS и stock licensing считать разными статьями расходов.

## Проба G. Языки, публикация, обратная связь — этапы 5–6

- Один и тот же исходный материал → несколько языковых версий: factual consistency, адаптация примеров/терминов, темп/длина, captions, лицензия и согласие на voice clone.
- English/Russian/Ukrainian/Greek владелец проверяет лично. Для остальных — носитель/квалифицированный reviewer или явный статус «естественность не подтверждена». ASR, перевод назад и waveform не заменяют эту проверку.
- До теста реальной публикации определить платформы/account access и текущие правила. Не предполагать, что account credentials включены в skill, GPT Plus или архив. Не публиковать автоматически.
- Сначала private/draft upload с подтверждением владельца, корректные language/credits/thumbnail, затем проверка воспроизведения, captions и account analytics. В этом проходе готовый общий multilingual publisher из архива **не подтверждён**.
- Portfolio и выпускная частота пересматриваются по данным, а не по количеству установленных plugins.

## Шаблон записи результата

```text
trial_id / stage / class:
shell + version / Windows build:
tool + version/commit / model + provider:
input IDs/URLs + timestamps / auth mode:
expected checks:
actual artifact paths + source coverage:
errors / retries / human interventions:
elapsed / model tokens / API costs / usage limits:
rights + privacy observations:
PASS | PARTIAL | FAIL | BLOCKED:
what was not tested:
repeat result / next comparison:
```

PASS не переносится автоматически на другой язык, источник, профиль, модель, оболочку или версию. Результаты пользователя добавляются в Git только после удаления secrets и private account data.
